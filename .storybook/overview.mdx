## Find the right level

- **Foundation:** brand composition, color, typography, spacing and motion.
- **Components:** actions, feedback, fields, overlays, navigation, media and content.
- **Pages:** seven complete page templates, their relevant edge states and a separate Route States subgroup.
- **Lab:** retained visual explorations without a current production consumer.

## Implementation status

Page stories reuse the website's presentation components. Case-study metadata and prose come directly from the four authored MDX files. Blog examples use clearly labelled content outside the public content directory; they do not publish a post. Storybook mocks Next.js routing and contact delivery, so production navigation, server loading and email delivery must still be verified on the website.

The case study diagram is the canonical local implementation, awaiting public MDX integration. Its Lab article is a review fixture; it does not replace the authored case study. Lab entries remain separate from the active page catalog.

## Review behavior

Use the Theme toolbar to inspect light and dark materials. Component Controls expose supported variants where they are useful. Check narrow layouts, keyboard operation, visible focus and reduced motion as well as the default appearance.

Story interaction and accessibility checks run in both themes. Automated scans require manual follow-up for inconclusive results and do not establish complete accessibility. Contact examples use an isolated transport and never send email.

The code and verification commands are documented in `docs/storybook.md`. This workshop is a local review artifact; nothing here is published by opening it.
