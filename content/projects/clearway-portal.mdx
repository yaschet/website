Students sent passports, IDs and transcripts to the study-abroad agency over WhatsApp. A passport arrived in one message, a transcript in another, and the remaining files came later. Staff had to piece each application together, chase what was missing and copy names, dates and grades into the agency's records. The information was already on the documents, but both sides still had more work to do.

The application also had to fit the student's circumstances. Someone waiting for final exam results still needed to start applying. Someone who began on a computer needed to continue on their phone. A single form that demanded every file in one sitting would not solve those problems.

I designed and built Portal to connect that entire journey. Students upload documents, check extracted details, save their progress and submit before every academic document is ready. They return to a dashboard to add the rest. Advisors receive the files and grades in the student records they already use.

I owned the product design and engineering from the client brief through production deployment: the four-language student experience, conditional application flow, document-processing integration and Laravel backend changes.

## Extract The Details, Then Let The Student Check

An ID already contains a name and date of birth. A transcript already contains grades. Asking the student to type them, then asking staff to enter them again, repeats the work and creates more opportunities for mistakes.

I connected the upload flow to document extraction using AWS Textract and OpenAI. An uploaded ID prefills identity fields; a transcript supplies grades for the student's academic record. Instead of treating the extracted text as unquestionable, the interface gives the student a chance to check it. Identity fields remain editable before confirmation.

Source badges make that review practical. A name filled from an ID is marked as coming from that ID, so the student knows why it appeared and what to compare it with.

The same connection continues into the advisor's workspace. Extracted grades stay linked to the original transcript, so an advisor can check the numbers against the document. That matters beyond filling in a profile: Phoenix, the program-matching system I built for the same agency, uses those academic records when evaluating university options.

The film follows one prepared example all the way through: Mathématiques **17,50 / 20** on the transcript becomes **17.50 / 20** on the advisor's record, with the source still available to inspect.

## Save Progress Beyond The Device

The student sees a focused question or upload at each step. Behind that simple interface, the next step depends on their answers: the degree they want, the qualifications they already hold and whether they have a passport.

I defined the steps and their conditions in typed configuration, separate from the screen components. The flow can ask for the relevant academic documents without sending every applicant through the same questions. Moving back, changing an answer and returning later all have to follow those conditions.

Progress is saved to the backend, including the answers and current step. Returning students recover the application from their account rather than relying on one browser's local storage. The film shows an academic goal saved on desktop, then restored in a separate session on an iPhone.

I built the experience in English, French, Arabic and Darija, including right-to-left layouts. The guided flow, document instructions and review screens follow the student's chosen language.

## Let Students Apply Before Every Document Is Ready

An application can be ready to begin before its documents are complete. Students finishing secondary school may still be waiting for final results. Requiring every transcript at the start would block them for something they cannot yet provide.

I separated submitting the initial application from completing the document collection. Students provide their core identity information and submit, then use the dashboard to see what has arrived and add the remaining files as they become available. Finishing the guided application does not make outstanding documents disappear.

The processing states matter here too. A successful upload means the file arrived, not that its contents have been read. I made uploading, processing, completion and failure visible as separate states. Documents that need extraction follow that path; administrative files that only need storage do not pretend to have been processed.

## Build On The Records The Agency Already Uses

A polished student portal would still leave the job unfinished if staff had to copy its submissions into another system. I connected Portal directly to the agency's existing customer records, including the attachments and academic grades that advisors need for their work.

My earlier work on Phoenix had exposed the difficulty of building this kind of continuous, interactive journey with our Livewire setup. I chose Next.js for the student interface while keeping Laravel responsible for the established records, validation, authorization and document processing.

That meant adapting the new application to the existing data model. Saving a step preserves the working application state and updates the relevant customer fields. Documents and extracted grades attach to that same customer. There is no second student database for the agency to reconcile.

Passports and transcripts also needed deliberate access controls. Authenticated requests run through Next.js server actions, with session tokens held in HttpOnly cookies. Laravel checks that a requested attachment belongs to the signed-in customer before issuing a temporary S3 download URL.

## From Application To Advisor

The result is a connected application process: students can start with the documents they have, check prefilled details, continue on another device and supply missing files later. Advisors can open the resulting record with the documents and grades already attached. The handoff no longer depends on staff re-entering what the student has already provided.

The walkthrough follows that handoff from the first ID upload through the matching grade in the advisor's record.
