For a translation agency, the finished job is a document the customer can use. Translating a scanned financial report also means keeping figures in the right rows, preserving names and headings, checking the wording and producing a file that can still be edited. If the table falls apart, the translator still has a document to rebuild.

I designed and built Verto around that complete job. A translator uploads the source, receives a structured translation, checks it beside the original and edits the result before generating a native Google Doc or downloading DOCX and PDF. The platform also keeps the customer, job history, agency branding and credit transactions connected to that work.

I owned the product from Figma designs through implementation and release: the application, document model, AI pipeline, review editor, export generator, customer management, payments and administration. Verto is an independent product, released in 2026.

The film follows a photographed English financial report into Japanese, then ends inside an editable table cell in Google Docs. It shows what the product delivers, from source document to a file the translator can continue working on.

## Preserve Structure Through Review

An automated translation still needs a translator's judgment. I put the source pages beside the translated document so the reviewer can compare a figure, check a name or correct a sentence without switching between disconnected files.

The editor supports changes to both wording and structure, including merging and splitting table cells. The reviewer is working on the document that will be delivered, so those corrections need to survive export.

I used a shared document model for paragraphs, headings and tables, including cells that span several rows or columns. The translation pipeline, Tiptap editor and export generator all work from that structure. Each correction has a defined place, and the generator has the information it needs to rebuild an editable table.

Names have an explicit preservation policy too. In the Japanese example, company and personal names stay in Latin script, making them directly comparable with the original. The product supports 68 target languages, including right-to-left output.


## Check Against The Original

The checking stage returns to the source page images after the first translation. It looks for issues such as missed content and table misalignment, then records its corrections and processing details. The original remains the reference throughout the job.

I built this as a separate pass because a completed AI response is not the same as a checked translation. The automated check helps find problems; the side-by-side editor gives the translator a place to make the final review before delivery.

## Carry Context Across A Long Document

A long report introduces a different problem. A term established near the beginning should not change meaning halfway through the document. Processing each group of pages in isolation would lose that continuity.

I carry names and terminology choices between batches, together with recent headings and a summary of the document so far. Later pages receive the context established by earlier ones. The film demonstrates that connection between pages 6 and 22 of the same document.

Arabic adds another requirement: reading direction must hold through the editor and the exported file, including the order of table cells. I handled direction in the document model and export logic so it remains part of the document throughout that journey.

## Generate A Native Google Doc

The difficult part of delivery was making the result editable outside Verto. I built a generator that turns the reviewed document model into native Google Docs paragraphs, headings, tables, headers and footers.

A table with merged cells cannot be recreated by placing its text in a sequence. A cell may occupy several rows or columns, and every later cell must land in the correct position. The generator first builds a complete grid in memory, marks the space each cell occupies, then creates and merges the cells through the Google Docs API. Right-to-left tables require their cell order to be handled explicitly as well.

This is the handoff the film closes on: the user clicks into a real Google Docs table cell, edits it and uses Tab to move between cells. The output is a working document. The same generation flow also supports DOCX and PDF, with the agency's logo, stamp and certification text.

## Build The Business Around The Document

I built customer management, translation history, account settings and administration alongside the document workspace. Each translation can stay connected to the agency's customer, while branding settings control the identity on the delivered file.

Processing also needs to work when the user leaves the page or a job fails. Translation and generation run through Trigger.dev background tasks, with saved stages, status updates and failure details. A user can return to the result for review and export instead of keeping the upload page open throughout processing.

Stripe purchases fund the credit balance used by those jobs. I implemented deductions, transaction history, credit adjustments and refunds for failed processing. Refund handling checks for an existing refund linked to the translation, so a retry can recognize one already recorded. Users can see the cost and refund in the same history as the job.

Together, these parts turn the document pipeline into a complete product for agency work: create a job for a customer, process the source, check and edit the translation, then deliver a branded, editable file.
